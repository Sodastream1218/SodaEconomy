# SodaEconomy Code of Conduct

## Our commitment

SodaEconomy aims to maintain a respectful, technically constructive, and welcoming project space.
Everyone participating in issues, pull requests, discussions, reviews, or other project channels is
expected to follow this code of conduct.

## Expected behavior

Examples of positive participation include:

- communicating respectfully and focusing criticism on ideas or code;
- providing reproducible technical information and constructive feedback;
- accepting that maintainers may decline requests based on scope, safety, or compatibility;
- respecting different levels of experience and helping contributors improve;
- protecting private information and reporting security-sensitive matters privately;
- acknowledging mistakes and correcting them in good faith.

## Unacceptable behavior

The following behavior is not acceptable:

- harassment, threats, discrimination, insults, or personal attacks;
- sexualized language or unwanted attention;
- deliberate disruption, spam, repeated off-topic demands, or bad-faith reporting;
- publishing private information without permission;
- pressuring maintainers for immediate support or guaranteed delivery dates;
- attempting to exploit, duplicate, corrupt, or steal server economy data;
- publicly disclosing an unresolved security vulnerability or sensitive exploit details.

## Scope

This code applies in all official SodaEconomy project spaces, including GitHub issues, pull requests,
discussions, project boards, release comments, and community spaces explicitly represented as
SodaEconomy channels.

## Enforcement

Maintainers may edit, hide, lock, or remove content and may temporarily or permanently restrict
participation when behavior violates this policy. Enforcement decisions should be proportionate,
documented when appropriate, and focused on protecting the project and its participants.

For conduct concerns, contact the project maintainer through a private contact method listed on the
maintainer's GitHub profile. Do not post sensitive reports publicly. GitHub's built-in report and
block tools may also be used for platform-level abuse.

## Good-faith technical disagreement

Technical disagreement is welcome. A rejected feature, closed issue, requested test, or critical code
review is not by itself a conduct violation. Participants should assume good faith while still
allowing maintainers to enforce the project's architecture and release standards.
